# Content engine

`packages/engine` keeps `content/` in sync with the sources. Run it from the repository root (`pnpm engine …`).

| Command | Does |
|---|---|
| `pnpm engine run [--sources a,b] [--limit N] [--max-minutes M] [--only <url regex>]` | discover → fetch (real Chrome, ≥5 s per source) → snapshot to `sources/` → Claude classify + translate + review → merge into `content/` → photos → changelog |
| `pnpm engine card-fill [--sources a,b] [--limit N] [--only <url regex>]` | species pages whose data card lacks a figure (as a public build shows it), most-read first: their profiles on in-depth sources that haven't given the page any text yet (found by the name in the address; Seriously Fish, Loaches Online and ScotCat unless `--sources`), read like any page with `run`'s prompt rules and guards; `--limit` pages a source (10); prints what each page gained. Run by the cycle on Seriously Fish (`CARD_FILL_LIMIT`) |
| `pnpm engine summaries [--top N] [--jobs N] [--only id,id]` | "Tóm tắt nhanh" + common mistakes for every published species without one (or whose page changed), most-read first, from its translated text and data card → `content/summaries/`. Each draft is checked: temperature, pH, hardness, adult size, minimum tank and difficulty figures must be the card's and every other number written on the page (a rule), and a second model call checks every claim against the text; a draft with problems is rewritten once with them. Passing ones are approved (the site shows approved ones only), the rest stay pending with their problems in `docs/review/summaries.md`. `--jobs`: species at a time; `--only`: redo these species whatever their state. Run by the cycle |
| `pnpm engine summaries approve <id,id\|all>` | approve pending summaries by hand, after correcting them |
| `pnpm engine traits [--limit N]` | temperament, fin-nipping, minimum school size from each species page's text → `content/traits/` (tank-mates checker); run by the cycle |
| `pnpm engine gallery [--sheets N] [--only id] [--shard i/n]` | species and plant galleries topped up to their tier's target (`gallery-plan.ts`), most popular first: iNaturalist, Commons, GBIF, Openverse (open licences, read per photo) → shared screening → `content/gallery/`; each page's place in `engine-state/gallery/`; shortfall in `docs/review/galleries.md`; `--sheets` model calls; run by the cycle. Optional `OPENVERSE_CLIENT_ID` / `OPENVERSE_CLIENT_SECRET` (a registered Openverse app) lift Openverse's 200 anonymous requests a day |
| `pnpm engine shop-list --lang vi\|id\|th [--kind plants]` | what fish (or plant) shops in that country sell, researched from their own lists (never marketplaces) → `engine-state/shop-lists/` (ranks new pages and galleries) |
| `pnpm engine thumbs` | 480px card thumbs for photos stored before thumbs existed; run by the cycle |
| `pnpm engine metric` | fish, plant, breed and guide pages (vi, id, th) in metric only: °F, inches, feet, gallons and pounds a writer left are converted, an imperial figure beside its metric one dropped (`@aq/schema` `toMetric`); every writer of those pages applies it too; a guide whose topic was checked stays checked; run by the cycle before the build |
| `pnpm engine sweep [--titles N]` | the content rules' safe fixes on every page, each cycle after `metric` (`sweep.ts`; the real-content test fails on any left): the source site's comments, comment form and related posts cut; empty headings, the later copy of a repeated paragraph and labels out of order ("Sai lầm 1, 9, 2…") fixed; a photo whose caption names another fish the site has, or is a map, taken off its page (and off every page through `engine-state/_photo-rejected.json` unless another page it is on is that fish's); a card figure out of bounds, upside down or a tank shorter than twice the fish hidden (`hidden`, kept in the file), its approved summary sent back to be written again; a title promising a count its text lacks rewritten by the model (`--titles` a run, default 3, reviewer-gated; 0: none) or its number dropped, the address kept. Each file keeps its indentation and date |
| `pnpm engine facebook [--limit N] [--max-minutes M] [--retry-blocked] [--backfill]` | Jim Cumming's Facebook (posts, albums) → full-size originals in R2 `facebook/` + snapshots in `sources/facebook-jim/` → species in his photos (Claude, high confidence only, `--limit` model calls) → species galleries |
| `pnpm engine audit [--fix]` | reports, nothing hidden: pictures per page (`docs/review/content-audit.md`) and every published page in each language against the content rules (`docs/review/content-rules.md`, docs/governance.md); `--fix` first makes the rules' safe fixes on the stored text, as the engine does when it writes a page; run by the cycle |
| `pnpm engine reader [--limit N] [--rewrites N] [--only lang/kind/id,…] [--popular]` | a reader's eye: the model reads `--limit` pages (default 20; not read yet first, then changed ones) against `prompts/reader.md`; Vietnamese wording it flags, and text a content rule sends it ("Trang lưu ý…"), is rewritten, reviewer-gated, `--rewrites` parts at most (default 3); findings in `docs/review/reader.md`, state in `engine-state/_reader.json`; `READER_MODEL` sets the reading model (default opus); run by the cycle. `--popular`: a backfill, the most-read pages first (Vietnamese; the species and plants most kept and sold, then guides) |
| `pnpm engine status` | URL counts per source and status from `engine-state/`; thin species pages by source and the most popular ones (docs/governance.md, page depth) |

- Fetching uses headed Chrome (`~/.cache/thuysinh/chrome-profile`). A challenge page marks the source `needs-human`: open that profile, pass the check by hand, and the next run continues. No stealth or solvers.
- Translation: `claude -p --model sonnet` on the owner's subscription with a lean prompt; a second pass scores it. Scores under 0.75 get one re-translation with the reviewer's notes, and are noindexed if still low. Thin species pages are noindexed too, and their in-depth sources' pages fetched first (docs/governance.md, page depth).
- Facebook: a **spare** Facebook account is logged into the engine Chrome profile by hand (not the owner's own). Run `pnpm engine facebook --backfill` by hand first (whole timeline and every album, up to 10 h), again until it prints no `warning:` lines; normal runs only read what's new at the top. Logged out or at a checkpoint, the run stops and `facebook-jim` is blocked until `pnpm engine facebook --retry-blocked`. Originals sit unconverted at `https://media.aquatome.com/facebook/<photo id>.<ext>` (public, not linked from the site). State: `engine-state/facebook-jim-crawl.json` (crawl) and `facebook-jim-photos.json` (one decision per photo). Re-capture parser fixtures with `packages/engine/scripts/fb-recon.ts` + `fb-fixtures.ts` when Facebook changes.
- Photos: the best few photos on each source page are copied to R2 `thuysinh-media` (≤1200 px WebP, `https://media.aquatome.com`) and credited to the source page. They follow the source's publish flag. Wikimedia Commons (open licences) is the fallback.
- Credentials (never committed): `~/.config/thuysinh/cf-token` and `~/.config/thuysinh/cf-account`, or `CLOUDFLARE_API_TOKEN` / `CF_ACCOUNT_ID`. Optional: `YOUTUBE_API_KEY` for videos.
- Schedule: GitHub Actions `engine.yml` runs `scripts/engine-cycle.sh` (pull → run → test → commit + push → deploy) every 3 h as three parallel jobs, each publishing its own part: `pages` (new pages), `photos` (photo upkeep), `rewrite` (older Vietnamese). `pages` and `photos` use macOS runners (face screening uses Apple Vision; the fetcher drives a headed Chrome). The engine-state photo caches merge through `scripts/merge-json-map.mjs` (`.gitattributes`). Manual run: `gh workflow run engine.yml -f engine_args="--sources scotcat --limit 2"`. `moderate.yml` moderates comments and reader photos nightly; `deploy.yml` deploys every merge to main; `ci.yml` tests PRs. Secrets: `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`), `CLOUDFLARE_API_TOKEN`, `AB_DASH_TOKEN`; variable `CF_ACCOUNT_ID`.
- YouTube steps (videos → guides, their species and kit, playlist discovery) run on the owner's Mac, because YouTube throttles GitHub's IPs: `scripts/install-video-schedule.sh` installs `run.thuysinh.videos` (`scripts/video-cycle.sh` every 3 h; log `~/Library/Logs/thuysinh-videos.log`). It also starts the GitHub engine workflow when that hasn't run for 3 hours (GitHub's cron drops slots). Video metadata comes from the YouTube Data API (`~/.config/thuysinh/youtube-api-key` or `YOUTUBE_API_KEY`), so yt-dlp only fetches captions; `~/.config/thuysinh/yt-cookies-from` (e.g. `chrome:Profile 2`) signs yt-dlp in. `content/changelog.json` merges through `scripts/merge-changelog.mjs` (`.gitattributes`).
- On a Mac instead: `scripts/install-engine-schedule.sh` installs the launchd agent `run.thuysinh.engine` (same script, every 6 h, from a dedicated clone; log `~/Library/Logs/thuysinh-engine.log`). Don't run both.
