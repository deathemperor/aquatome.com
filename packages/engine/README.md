# Content engine

`packages/engine` keeps `content/` in sync with the sources. Run it from the repository root (`pnpm engine …`).

| Command | Does |
|---|---|
| `pnpm engine run [--sources a,b] [--limit N] [--max-minutes M] [--only <url regex>]` | discover → fetch (real Chrome, ≥5 s per source) → snapshot to `sources/` → Claude classify + translate + review → merge into `content/` → photos → changelog |
| `pnpm engine card-fill [--sources a,b] [--limit N] [--only <url regex>]` | species pages whose data card lacks a figure (as a public build shows it), most-read first: their profiles on in-depth sources that haven't given the page any text yet (found by the name in the address; Seriously Fish, Loaches Online and ScotCat unless `--sources`), read like any page with `run`'s prompt rules and guards; `--limit` pages a source (10); prints what each page gained. Run by the cycle on Seriously Fish (`CARD_FILL_LIMIT`) |
| `pnpm engine summaries [--top N] [--jobs N] [--only id,id]` | "Tóm tắt nhanh" + common mistakes for every published species without one (or whose page changed), most-read first, from its translated text and data card → `content/summaries/`. Each draft is checked: temperature, pH, hardness, adult size, minimum tank and difficulty figures must be the card's and every other number written on the page (a rule), and a second model call checks every claim against the text; a draft with problems is rewritten once with them. Passing ones are approved (the site shows approved ones only), the rest stay pending with their problems in `docs/review/summaries.md`. `--jobs`: species at a time; `--only`: redo these species whatever their state. Run by the cycle |
| `pnpm engine summaries approve <id,id\|all>` | approve pending summaries by hand, after correcting them |
| `pnpm engine traits [--limit N]` | temperament, fin-nipping, minimum school size from each species page's text → `content/traits/` (tank-mates checker); run by the cycle |
| `pnpm engine gallery [--sheets N] [--only id] [--shard i/n]` | species, plant and breed galleries topped up to their tier's target (`gallery-plan.ts`), most popular first: iNaturalist, Commons, GBIF, Openverse (a breed: Commons and Openverse by its English and trade names; open licences, read per photo) → shared screening → `content/gallery/`; each page's place in `engine-state/gallery/`; shortfall in `docs/review/galleries.md`; `--sheets` model calls; run by the cycle. Optional `OPENVERSE_CLIENT_ID` / `OPENVERSE_CLIENT_SECRET` (a registered Openverse app) lift Openverse's 200 anonymous requests a day |
| `pnpm engine shop-list --lang vi\|id\|th [--kind plants] [--seed file.json]` | what fish (or plant) shops in that country sell, researched from their own lists (never marketplaces) → `engine-state/shop-lists/` (ranks new pages and galleries); a seed (one shop's trade names) adds only the species the kept list lacks, after it |
| `pnpm engine ideas [--force] [--retry-blocked]` | Vietnamese shops' blogs and a British magazine, their posts' titles only, a week apart → the topics the handbook has no guide on, most asked first, the magazine's behind the shops' (`engine-state/_ideas.json`); a site that refuses its listing needs the owner and is read again only with `--retry-blocked` |
| `pnpm engine write-ideas [--limit N]` | AquaTome's own guides on the most asked ideas, N a day (2 in the cycle, `IDEAS_PER_DAY`), researched as `pnpm engine topic` is, the shops' posts as leads never copied |
| `pnpm engine check-photos [--limit N] [--only id]` / `recheck-photos [--limit N]` | every photo on a species, plant or breed page and its gallery judged against its subject (`photo-check.ts`): another fish or no photo of it (a landscape with no fish too) off the page; a dead fish, fish as food, a person or a hand, or an added logo off every page and onto `engine-state/_photo-rejected.json`. A verdict from before the check asked about people is asked again. `recheck-photos`: those first, once, whose earlier notes say a dead fish, a hand or a person, or whose verdict was the old "habitat"; then none. Both run by the cycle |
| `pnpm engine guide-photos [--limit N]` | guides' photos (leads first) and their video sections' photos, equipment guides' photos, then video guides' stills, 6 to a model call (`guide-photos.ts`): a person or a hand, or a mark added on the photo, off every page and onto `engine-state/_photo-rejected.json`; a shop's or maker's brand on a product off the guides (kept on an equipment guide and on a still). A still is judged once it is the video's own frame or a tile `video-stills` keeps. Each judged once (`engine-state/_photo-guides.json`); run by the cycle and the video job |
| `pnpm engine thumbs` | 480px card thumbs for photos stored before thumbs existed; run by the cycle |
| `pnpm engine plant-synonyms` | each plant's other scientific names → `synonyms` on its page: the former names its sources give ("Previously named …", "formerly …", "syn. …"), GBIF's (its accepted name and that name's synonyms, cached in `engine-state/_gbif-synonyms.json`) and the few hobby names in `HOBBY_NAMES`; a name another page uses, or two plants would take, is left out. The site links, checks and searches them as the plant's own; run by the cycle |
| `pnpm engine metric` | fish, plant, breed and guide pages (vi, id, th) in metric only: °F, inches, feet, gallons and pounds a writer left are converted, an imperial figure beside its metric one dropped (`@aq/schema` `toMetric`); every writer of those pages applies it too; a guide whose topic was checked stays checked; run by the cycle before the build |
| `pnpm engine sweep [--titles N]` | the content rules' safe fixes on every page, each cycle after `metric` (`sweep.ts`; the real-content test fails on any left): the source site's comments, comment form and related posts cut; a heading with nothing under it (at the end, or over one not its sub-section; a group over its sub-sections stays), the later copy of a repeated paragraph and labels out of order ("Sai lầm 1, 9, 2…") fixed; a photo whose caption names another fish the site has, or is a map, taken off its page (a map off every page through `engine-state/_photo-rejected.json`); a card figure out of bounds, upside down or a tank shorter than twice the fish hidden (`hidden`, kept in the file), its approved summary sent back to be written again; a guide's title promising a count its text lacks rewritten by the model (`--titles` a run, default 3, reviewer-gated; 0: none) or its number dropped, the address kept; a breed linked to the species page its research names (what it is a form of, its parents' pages) where it has none and exactly one page is that species, by name or a GBIF synonym (`engine-state/_breed-links.json`). Each file keeps its indentation and date |
| `pnpm engine facebook [--limit N] [--max-minutes M] [--retry-blocked] [--backfill]` | Jim Cumming's Facebook (posts, albums) → full-size originals in R2 `facebook/` + snapshots in `sources/facebook-jim/` → species in his photos (Claude, high confidence only, `--limit` model calls) → species galleries |
| `pnpm engine audit [--fix]` | reports, nothing hidden: pictures per page (`docs/review/content-audit.md`) and every published page in each language against the content rules (`docs/review/content-rules.md`, docs/governance.md); `--fix` first makes the rules' safe fixes on the stored text, as the engine does when it writes a page; run by the cycle |
| `pnpm engine reader [--limit N] [--rewrites N] [--only lang/kind/id,…] [--popular]` | a reader's eye: the model reads `--limit` pages (default 20; not read yet first, then changed ones) against `prompts/reader.md`; Vietnamese wording it flags, and text a content rule sends it ("Trang lưu ý…"), is rewritten, reviewer-gated, `--rewrites` parts at most (default 3); findings in `docs/review/reader.md`, state in `engine-state/_reader.json`; `READER_MODEL` sets the reading model (default opus); run by the cycle. `--popular`: a backfill, the most-read pages first (Vietnamese; the species and plants most kept and sold, then guides) |
| `pnpm engine review-backfill [--kind video-guide,translation,localize,places] [--limit N] [--only id,id \| --reviewed-before <ISO time>] [--parallel N]` | pages under the bar whose review left no notes, reviewed again as they are, nothing rewritten: each gets its score and notes in `engine-state/reviews/` (`review-log.ts`, docs/governance.md). `--limit`: model calls a kind (default 10); `--only`: these pages whatever their score; `--reviewed-before`: every page with no review from that time on, whatever its score (after a reviewer's prompt changed), each once, video guides the riskiest first, then the most read (`video-order.ts`); `--parallel N` at once. Video guides read their transcripts (on the Mac), the owner's videos first; run by the cycles. `pnpm engine videos --redo --rechecked-since <ISO time> [--limit N] [--parallel N]` writes again, from their notes, the guides such a recheck left under the bar, each once (`scripts/video-recheck.sh`, hourly) |
| `pnpm engine video-hold --class risk1\|risk2\|risk3\|all [--clear]` | holds a risk group of video guides (`video-order.ts`: medicine and treatments, water, the rest) out of the chat until each passes the stricter reviewer: `quality.chat: false` in each language file, cleared by a passing recheck or redo (`video-hold.ts`, docs/governance.md); `--clear` lets the group back in |
| `pnpm engine reviews` | what every quality review kept (`engine-state/reviews/`), per kind: pages under the bar and the faults their notes name most, grouped, with notes quoted and their pages → `docs/review/reviews.md`; run by the cycle |
| `pnpm engine status` | URL counts per source and status from `engine-state/`; thin species pages by source and the most popular ones (docs/governance.md, page depth) |

- Fetching uses headed Chrome (`~/.cache/aquatome/chrome-profile`), minimized as soon as it has opened so the owner's screen stays theirs: `scripts/chrome-windows.py` says whether any is on it. A challenge page marks the source `needs-human`: open that profile, pass the check by hand, and the next run continues. No stealth or solvers.
- Translation: `claude -p --model sonnet` on the owner's subscription with a lean prompt; a second pass scores it. Scores under 0.75 get one re-translation with the reviewer's notes, and are noindexed if still low. Every review's score and notes are kept in `engine-state/reviews/<kind>.json` (`review-log.ts`), and a `--redo` gives the writer the last ones. Thin species pages are noindexed too, and their in-depth sources' pages fetched first (docs/governance.md, page depth).
- Facebook: a **spare** Facebook account is logged into the engine Chrome profile by hand (not the owner's own). Run `pnpm engine facebook --backfill` by hand first (whole timeline and every album, up to 10 h), again until it prints no `warning:` lines; normal runs only read what's new at the top. Logged out or at a checkpoint, the run stops and `facebook-jim` is blocked until `pnpm engine facebook --retry-blocked`. Originals sit unconverted at `https://media.aquatome.com/facebook/<photo id>.<ext>` (public, not linked from the site). State: `engine-state/facebook-jim-crawl.json` (crawl) and `facebook-jim-photos.json` (one decision per photo). Re-capture parser fixtures with `packages/engine/scripts/fb-recon.ts` + `fb-fixtures.ts` when Facebook changes.
- Photos: the best few photos on each source page are copied to R2 `aquatome-media` (≤1200 px WebP, `https://media.aquatome.com`) and credited to the source page. They follow the source's publish flag. Wikimedia Commons (open licences) is the fallback.
- Wanted pages first: species our pages name without having a page, popular ones we lack, and the names readers keep on
  their tanks without a page, most readers first (`readers-wanted.ts`: the site's Worker counts them in KV `AB` under
  `wanted:n:`, read through Cloudflare's API with the token below; without it the run goes on without them). The audit
  lists readers' names (`docs/review/content-audit.md`): a species GBIF knows at once, any other name once 3 readers
  gave it, since the report is public.
- Credentials (never committed): `~/.config/aquatome/cf-token` and `~/.config/aquatome/cf-account`, or `CLOUDFLARE_API_TOKEN` / `CF_ACCOUNT_ID`. Optional: `YOUTUBE_API_KEY` for videos.
- Schedule: `scripts/engine-cycle.sh <part>` (pull → run → test → commit + push, and the push deploys) every 3 h, four parts side by side, each publishing its own: `pages` (new pages), `sf` (Seriously Fish's pages), `photos` (photo upkeep), `rewrite` (older Vietnamese; Indonesian and Thai pages). `rewrite` runs on GitHub Actions (`engine.yml`). The other three need macOS (face screening uses Apple Vision; the fetcher drives a headed Chrome) and run on the owner's Mac, which leaves GitHub's macOS runners to the iOS app: `scripts/install-engine-schedule.sh` installs `run.aquatome.engine-pages`, `-sf` and `-photos`, each in its own clone (`~/.local/share/aquatome/engine-<part>`; log `~/Library/Logs/aquatome-engine-<part>.log`). `pages` uses the engine's Chrome profile (`~/.cache/aquatome/chrome-profile`), so pass a source's browser check there between its cycles. A Mac part that fails starts `engine-mac.yml`, which fails, so it shows with GitHub's failed jobs. The Mac's Claude accounts: `~/.config/aquatome/claude-oauth-tokens`, one token a line. The engine-state photo caches merge through `scripts/merge-json-map.mjs` (`.gitattributes`). Manual run, in that part's clone: `ENGINE_ARGS="--sources scotcat --limit 2" scripts/engine-cycle.sh pages`. `moderate.yml` moderates comments and reader photos hourly (its macOS job starts only when something waits); `deploy.yml` deploys every merge to main; `ci.yml` tests PRs. Secrets: `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`), `CLOUDFLARE_API_TOKEN`, `AB_DASH_TOKEN`; variable `CF_ACCOUNT_ID`.
- Claude accounts: `CLAUDE_CODE_OAUTH_TOKENS` holds several Claude subscription accounts' tokens, one a line, then `CLAUDE_CODE_OAUTH_TOKEN` (the first account) last when it isn't already listed. `fix.yml` uses `CLAUDE_CODE_OAUTH_TOKEN` alone, so its agent can reach one account only. Each call uses the first account not set aside; an account out of its usage limit, or whose token Claude rejects, is set aside for the rest of the command and the call goes to the next (`src/claude-accounts.ts`; the AI page review and `fix.yml` do the same). Each command that called Claude ends with what each token answered and why one was set aside, by number and hash, in the log and the run's summary page. To add an account: run `claude setup-token` signed in to it, and add the token as a new line of the `CLAUDE_CODE_OAUTH_TOKENS` secret (`gh secret set CLAUDE_CODE_OAUTH_TOKENS < file`, one token a line).
- YouTube steps (videos → guides, their species and kit, playlist discovery) run on the owner's Mac, because YouTube throttles GitHub's IPs: `scripts/install-video-schedule.sh` installs `run.aquatome.videos` (`scripts/video-cycle.sh` every 3 h; log `~/Library/Logs/aquatome-videos.log`). `scripts/install-video-recheck-schedule.sh` installs `run.aquatome.video-recheck` (`scripts/video-recheck.sh` hourly, in its own clone; log `~/Library/Logs/aquatome-video-recheck.log`): the guides checked again by the stricter reviewer and redone from its notes (docs/governance.md). It also starts the GitHub engine workflow when that hasn't run for 3 hours (GitHub's cron drops slots). Video metadata comes from the YouTube Data API (`~/.config/aquatome/youtube-api-key` or `YOUTUBE_API_KEY`), so yt-dlp only fetches captions; `~/.config/aquatome/yt-cookies-from` (e.g. `chrome:Profile 2`) signs yt-dlp in. A guide's stills are picked on YouTube's storyboard tiles, then taken from the video itself at the tile's second (ffmpeg seeking a ≤ 1280 px stream); `pnpm engine video-stills [--limit N] [--only id,id]` does the same for older guides (docs/governance.md, photos). `content/changelog.json` merges through `scripts/merge-changelog.mjs` (`.gitattributes`).
